# DESIGN.md — правила вёрстки проекта

Основа: публичные brand guidelines Vercel (vercel.com/design, Geist design system).
Следуем этим правилам при написании любого UI-кода проекта.

## Шрифты и типографика

- Шрифтовая пара: **Geist Sans** (весь UI, текст, цифры) + **Geist Mono** (только код, команды, пути, ID, таймстемпы; не для предложений и не для целых таблиц).
- Используем фиксированную шкалу типографских ролей, никаких произвольных размеров и весов:
  - `display` — только один главный заголовок страницы;
  - `title` — обычный заголовок страницы;
  - `heading-24` — крупные разделы; `heading-20` / `heading-16` — вложенная структура;
  - `lede` — один короткий вводный абзац; `body` — основной текст;
  - `label` — компактные подписи; `caption` / `meta` — подчинённый контекст.
- Вес: заголовки semibold, текст regular, выделения редки.
- Заголовки — **sentence case**. Запрещены ALL-CAPS «eyebrow»/overline и декоративная нумерация секций.
- `tabular-nums` для выровненных сравнений и таблиц с числами.
- Однотипные элементы (peers) всегда одного размера/веса/высоты строки. Не ужимать элемент потому, что текст длиннее.
- Длина строки прозы ~60–68 символов. Проблему переносов решаем правкой текста, а не уменьшением шрифта.
- Никаких em dash в UI-текстах.

## Сетка и выравнивание

- 12 колонок (desktop) / 6 (tablet) / 4 (mobile), общая сетка для хедера, контента и футера.
- Всё выравнивается по общим краям, базовым линиям или явным линиям грида.
- Проза — обычно 6–7 колонок; таблицы, графики, крупные сравнения — все 12.
- Гуттеры между колонками однозначные: текст соседних колонок не должен визуально сливаться.
- Крупное пустое пространство без причины — дефект вёрстки, не «воздух». Перекомпоновать.

## Вертикальный ритм (по отношениям, а не по одной шкале)

- Заголовок → первый абзац: близко.
- Абзац → абзац: один базовый ритм.
- Label → value → detail: одинаково у всех однотипных блоков.
- Блок → новая секция: заметно больше.
- Ориентиры: внутри групп `space-2`–`space-4`, между группами `space-6`–`space-8`, между секциями `space-8`–`space-12`; `space-16` — только под смысловой «chapter break».
- У каждого промежутка один «владелец» (spacing-обёртка типа stack/flow/grid); дети не добавляют свои конкурирующие margin.

## Цвет, поверхности, границы

- Дизайн в **монохроме**. Цвет — только для состояния, действия или данных; и никогда — «просто потому что приятный» (не красить «хорошее» значение в зелёный без смысловой причины).
- Одна непрерывная «канва» страницы. Поверхность/бордер — только когда несёт смысл (selection, реальная группировка, интерактив), а не по умолчанию как разделитель.
- Порядок средств иерархии: spacing → alignment → typography → density → и только потом бордеры/сurfейсы.
- **Не оборачивать каждую секцию/метрику в карточку. Не карточки-в-карточках.**
- Радиусы сдержанные и консистентные.
- Запрещено: декоративные градиенты, градиентный текст, glow, blobs, текстуры, glassmorphism, орнаментальные тени, фейковая глубина, бейджи-капсулы на обычном metadata, иконки в цветных плитках, стоп-имиджи и фейевые product-скриншоты. Градиент допустим только как подписанная непрерывная шкала данных.

## Плотность vs громкость (разная диагностика)

- Страница «занята» (busy) → удалить, объединить или перепорядочить контент.
- Страница «громкая» (loud) → убрать конкурирующий цвет, масштаб, вес, бордеры, motion.
- Один осознанный визуальный «якорь» на экран; вокруг него — тишина.
- Первый viewport — это суть/аргумент страницы, а не красивый masthead перед настройкой.

## Таблицы и данные

- Таблица — во всю ширину своей секции; вводный текст над таблицей, не сбоку.
- Текстовые колонки — left-align (заголовок тоже слева); числовые — **right-align, и заголовок тоже справа**.
- Ячейки выравниваются по первому текстовому baseline; не центрировать по вертикали.
- Единицы, периоды, базы сравнения — рядом с данными.
- Графики: честные шкалы (zero baseline для длин), пряме подписи вместо легенд, где возможно; один масштаб для всех сравниваемых полос.
- Не наливать «декоративные графики», если значения понятны текстом.

## Motion

- По умолчанию — покой. Motion только для объяснения смены состояния, непрерывности или подтверждения действия.
- Запрещены: marquee, parallax, reveal-on-scroll всей страницы, typing-курсоры, bounce, декоративная пульсация.
- Уважать `prefers-reduced-motion`.

## Мелочи, дающие «то самое» ощущение

- Один описательный `<h1>`, порядочные заголовки, skip-link.
- `min-width: 0` у детей grid/flex; reflow вместо сжатия; не прятать overflow.
- Простой и понятный focus-стиль; WCAG AA; не полагаться только на цвет.
- Без «generic centered hero + сетка одинаковых карточек».

## Чеклист перед коммитом UI

1. Есть один доминирующий объект? Пустые зоны осмысленные?
2. Все однотипные элементы совпадают по типографике и выравниванию?
3. Все бордеры/поверхности несут смысл? Что можно удалить без потерь?
4. В light и dark теме иерархия и контраст одинаково хороши?
5. Страница не разваливается на узких экранах?
